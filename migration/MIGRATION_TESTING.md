# Migration Testing — parity & regression infrastructure

## Existing harnesses

### 1. `scripts/rust_pdf_parity.py` — golden-file parity (Java ↔ Rust)

Drives both backends over real PDFs, fingerprints outputs, reports
semantic vs structural diffs.

- Inputs: `app/**/src/test/resources`, `app/**/test/resources`,
  `testing/` fixtures with `--include-testing`.
- Output fingerprint: `rust/examples/pdf_fingerprint.rs` (lopdf
  object-model: page boxes/rotation, annotations, fonts, content
  operators, /Info, catalog flags, object/stream counts). Byte equality is
  NOT expected across writers.
- Usage: `python3 scripts/rust_pdf_parity.py --include-testing --out /tmp/parity.json`
  Requires Java on :8080 (`task backend:dev`) and Rust on :8081
  (`task rust:dev`); `--case`, `--limit`, `--strict-structure` flags.
- Known divergences are tagged `known` so real regressions stand out.

### 2. `testing/parity.sh` — live endpoint parity

Compares migrated endpoints Java↔Rust: JSON via `jq -S`, PDFs via
`rust/examples/pdfdiff` (structural compare). Env: `JAVA_URL`, `RUST_URL`.
Run after every migrated batch.

### 3. `rust/tests/scripts/` — Rust-only smoke + unit gate

- `test-all.sh` = fmt + clippy + `cargo test` + `test-security.sh` +
  `test-general.sh`.
- Scripts boot `stirling-server` with `JAVA_BACKEND_URL=off` on
  `SMOKE_PORT` (default 18099) and POST generated fixtures from
  `rust/tests/fixtures/` (regenerated by `testkit::fixture_tests` on each
  `cargo test`).

### 4. Rust unit tests

`#[cfg(test)]` modules across `src/` (handlers, pdfdoc, page_select,
upload, imgcomp, forms, attachments, settings, endpointconfig, auth,
metrics, passwords, convert, platform…) using `src/testkit.rs` to build
PDFs in memory — no fixture files needed. ~167 tests as of the latest
green `cargo test` run; gate is `cargo fmt --check` +
`cargo clippy --all-targets -- -D warnings` + `cargo test`.

### 5. `rust/engine` tests

`cargo test` in `rust/engine` (contracts, chunking regression tests vs
Python outputs, document store tests). Python-side pytest suite
(`engine/`) remains the oracle; not yet ported.

## Gaps in coverage

- No automated Java↔Rust *JSON* parity for analysis endpoints beyond the
  fingerprint script (which covers PDFs); error-shape comparison is manual.
- Live parity sweep (`testing/parity.sh`, `rust_pdf_parity.py`) has not
  been re-run since the route set grew to ~112 — P1 in
  `migration/REMAINING_WORK.md`.
- Async-job parity (status JSON fields, ISO vs epoch timestamps) not under
  automated diff.
- Auth/settings-gated behavior: Rust now has `auth.rs`/`guard.rs` +
  `endpointconfig.rs`, but parity vs Java's filter chain is untested
  end-to-end.
- `rust/tests/integration/` is reserved/empty — no HTTP-level Rust↔Java
  contract tests yet.
- No CI job runs the live parity harness (needs both servers); `task
  rust:check` is lint+unit only.

## Recommended next testing investments (in order)

1. Wire `parity.sh`/`rust_pdf_parity.py` into a repeatable per-batch
   checklist (already the documented workflow — enforce it).
2. Add JSON deep-diff mode for analysis endpoints (normalize only
   timestamps/IDs).
3. Extend `rust/tests/integration/` with axum `tower::ServiceExt::oneshot`
   tests hitting the real router (catches route/DTO drift without a server).
4. Golden tests for job endpoints: submit `?async=true`, poll, compare
   result JSON modulo `jobId`/timestamps.
