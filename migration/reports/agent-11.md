# Agent 11 — Form API: field inspection and CSV extraction

Scope: `app/core/.../controller/api/form/FormFillController.java` — all nine
`/api/v1/form/*` endpoints. Read side migrated natively; mutation side stays
on the Java proxy.

## Controller inventory

| Endpoint | Status |
|---|---|
| `POST /api/v1/form/fields` | **Native** — `form::list_fields` |
| `POST /api/v1/form/fields-with-coordinates` | **Native** — `form::list_fields_with_coordinates` |
| `POST /api/v1/form/extract-csv` | **Native** when no `data` part (or empty); forwards to Java when `data` is a non-empty JSON values file, because Java applies `FormUtils.applyFieldValues` before extracting |
| `POST /api/v1/form/extract-xlsx` | Proxied — POI workbook output |
| `POST /api/v1/form/add-fields` | Proxied — widget appearance generation |
| `POST /api/v1/form/edit-fields` | Proxied — appearance regeneration |
| `POST /api/v1/form/modify-fields` | Proxied — appearance regeneration |
| `POST /api/v1/form/delete-fields` | Proxied — field-tree surgery + appearance cleanup |
| `POST /api/v1/form/fill` | Proxied — `applyFieldValues` + appearances |

XFA forms need no special-casing: `PDAcroForm.getFieldTree()` only walks
`/Fields`, so XFA-only documents yield an empty field list on both sides.

## Implementation

New module `rust/src/handlers/form.rs` (~1,500 lines). The field walk
mirrors `FormUtils`/`PDFieldFactory`:

- A node is non-terminal when any `/Kids` entry resolves to a dictionary
  carrying a `/T` string; otherwise terminal. Qualified names join partial
  `/T` values with `.`, including the `parent.` trailing-dot edge case for
  empty-string partial names.
- Field type comes from the nearest `/FT` walking `/Parent`-then-`/P`
  (depth-capped like PDFBox's `seen` set); `/Ff` is read from the node's
  own dictionary only — `PDFieldFactory` uses `COSDictionary.getInt`, not
  the inheritable lookup.
- `Tx`/`Sig`/`Ch`(combo flag 1<<17)/`Btn`(radio 1<<15, pushbutton 1<<16)
  classification matches `createChoiceSubType`/`createButtonSubType`.
- Widgets: no `/Kids` → the field dict itself; otherwise every kid
  dictionary (subtype unchecked); empty/all-non-dict `/Kids` → none.
- Inheritable lookups (`/V` for text/buttons, `/DA`, button `/Opt`) walk
  own dict then traversal ancestors, matching `getInheritableAttribute`.
  Choice `/V` and `/Opt` are own-dict only, matching
  `PDChoice.getValueFor`/`getOptions`.
- Choice `/Opt` entries resolve one level (the Java
  `resolveIndirectChoiceOptions` repair), while pair-array elements must
  remain direct strings — matching `getPairableItems` after repair.
- Button `/Opt` array elements are NOT resolved
  (`toCOSStringStringList` semantics).
- Values: choice joins selected values with `,`; text reads inherited
  `/V` string-or-stream; buttons read inherited `/V` name with `/Opt`
  numeric-index resolution, else `"Off"`; signatures emit no value.
- Labels port `deriveDisplayLabel` exactly: `/TU` alternate → tooltip →
  humanized name → first option for auto-generated choice names →
  humanized → `fallbackLabelForType`, with the `looksGeneric` /
  `looksAutoGenerated` regex semantics hand-rolled (no regex crate).
- Page index: `/Annots` reference→first-page map (`putIfAbsent` order),
  then `/P` back-reference following reference chains to the final object
  id. The Java annotation-rescan fallback is provably redundant: it only
  matches on `COSDictionary` identity, which an inline `/Kids` dict can
  never share with an `/Annots` entry.
- Widget coordinates replicate `createWidgetCoordinates`: CropBox-relative
  X, `cropHeight − relY − height` Y-flip, finite-only acceptance, plus the
  field-as-own-widget `/Rect` fallback when the widget list is empty.
  Computed in `f32` and emitted through serde `f32` fields so JSON floats
  match Jackson's `Float` shortest-round-trip formatting.
- Ordering: `/fields` and CSV use `extractFormFields` sort
  (pageIndex, pageOrder, case-insensitive name); coordinates keeps tree
  order then applies the stable `FieldCoordinateComparator` (first-widget
  page, 10pt same-line y-band → x, then y).
- CSV replicates OpenCSV defaults (`,` separator, minimal quoting, `\n`)
  and `CsvSanitizer` (formula-trigger prefix `'`, `PLAIN_NUMBER` exemption,
  `stripLeading` semantics).
- Templates replicate `buildFillTemplateRecord` (checkbox→bool, listbox→
  `[]`/string, button+signature skipped, last-write-wins on duplicate
  names).

Response shapes use `#[derive(Serialize)]` structs mirroring the Java
records (`FormFieldInfo`, `FormFieldWithCoordinates`, `WidgetCoordinates`)
with `skip_serializing_if` for NON_NULL members — preserving Java's JSON
key order and float formatting.

## Limitations / divergences

- `extract-csv` with a non-empty `data` part forwards to Java (applies
  field values first). Empty `data` takes the native path, matching
  `data.isEmpty()`.
- `Content-Disposition` uses the shared `file_response`
  (`filename="..."`) rather than Java's `filename*=UTF-8''` encoding —
  same as every other native file endpoint.
- Template object keys serialize sorted (serde_json `Map` is a BTreeMap
  without `preserve_order`); Java emits LinkedHashMap order. Key order is
  semantically irrelevant to JSON clients.
- `find_field_type`'s cycle guard is a depth cap rather than PDFBox's
  dictionary-identity set — only observable on adversarial cyclic `/Parent`
  chains beyond 64 levels.
- `String.toLowerCase()`/`trim()` approximations used for
  `compareToIgnoreCase`, `stripLeading`, and case-insensitive regex
  equivalents; Unicode edge cases may differ marginally.
- No build or test run per task restrictions; verification was source-level
  only (Java controller, `FormUtils`, PDFBox sources, Rust helper
  signatures).

## Dependencies

None added. Uses existing `lopdf`, `serde`/`serde_json`, axum multipart,
`pdfdoc`, `dispatch` (async-job aware), and `proxy::forward_parts`.

## Route registration

Already present in `rust/src/handlers/mod.rs`:

```rust
.route("/api/v1/form/fields", post(form::list_fields))
.route("/api/v1/form/fields-with-coordinates", post(form::list_fields_with_coordinates))
.route("/api/v1/form/extract-csv", post(form::extract_csv))
```

All other `/api/v1/form/*` paths fall through to the Java proxy.
